# МТС Energytool — фронтенд

React 19 + TypeScript + Vite. Интерфейс повторяет 22 экрана и состояния страницы **«Консультант v2»** в [Figma](https://www.figma.com/design/NsFKHEsWB7tR7pY4pzThhY/?node-id=73-218).

## Запуск

Нужен Node.js 22.12+ или 24+.

```sh
npm ci
npm run dev
```

Открыть http://localhost:5173. Для production: `npm run build`, затем `npm run preview`. На хостинге маршруты приложения должны перенаправляться на `index.html`.

По умолчанию включены **моки**. Для работы с HTTP API:

```sh
npm run dev:api
```

Адрес backend пока оставлен пустым: запросы идут на `/api/v1` того же origin. Когда backend будет готов, скопировать `.env.example` в `.env.local` и задать `VITE_API_BASE_URL` (полный prefix, например `https://backend.example/api/v1`) либо настроить `API_PROXY_TARGET` для локального reverse proxy. Для production API-сборки: `npm run build:api` → `dist-api/`. Обычная сборка сохраняет моки. Также режим можно выбрать через `VITE_DATA_SOURCE=mock|api` в `.env.local`.

Переменные `VITE_*` являются публичными настройками сборки. API-ключи и токены в них не помещать. При изменении окружения перезапустить Vite / пересобрать приложение. Автоматической подмены ошибок API моковыми ответами нет.

## Страницы

- `/` — старт консультации.
- `/chat/:sessionId` — активный или архивный диалог.
- `/archive` — архив результатов: сортировка, страницы, размер страницы, скачивание CSV.
- `/demo` — каталог всех 22 состояний Figma. Каждый пример интерактивен и использует отдельное хранилище в памяти, не меняя обычную историю.
- `/review` — защищённый просмотр серверной истории, подтверждённых заявок и черновиков; по умолчанию закрыт.

На телефоне кнопки над чатом открывают историю и отладку. В desktop-версии история сворачивается в узкую панель. Содержимое диалога прокручивается независимо от поля ввода.

## Проверка сценариев

1. Написать: «Мы стали больше работать вечером, и счёт вырос. Можно разобраться, из-за чего?».
2. Выбрать «Не знаю. Где это посмотреть?», затем «Обычный счётчик».
3. Открыть «Подробнее» у продукта и нажать «Обсудить стоимость».
4. Выбрать «Да, передайте». Ввести выдуманные ФИО, телефон из 11 цифр с 7 или 8, компанию и отметить согласие.
5. Отправить заявку: появятся подтверждение и резюме. Обновить страницу — заявка и история сохранятся.
6. Нажать «Новый диалог» и подтвердить сброс. Открыть прошлую сессию: она доступна только для чтения. «Продолжить в новом диалоге» копирует переписку в новую сессию, сохраняя оригинал.

Дополнительные моковые ветки:

- «Ставите ли вы зарядные станции для электромобилей?» — нет информации в базе.
- «А отключать должников без суда законно?» — вне компетенции.
- «А солнечные панели нам подойдут?» — смена темы; «Вернёмся к счёту» — возврат к первой теме.
- В DevTools перевести браузер в Offline, отправить сообщение, затем вернуть Online и нажать «Повторить». Сообщение сохраняется и повторяется без дубля.
- Пустая история, индикатор набора ответа, ошибка телефона, подтверждение сброса и другие состояния доступны непосредственно в `/demo`.

## API и архитектура

Источник HTTP-контракта — переданный `docs/openapi.yaml`. `src/api/schema.d.ts` сгенерирован из него; для обновления запустить `npm run api:generate`. Не менять сгенерированные типы вручную. Бизнес-типы интерфейса и `ChatService` описаны отдельно в `src/types.ts`.

`src/api/client.ts` — HTTP-клиент с timeout, bearer сессии, типизированными ошибками, `X-Request-ID` и `Retry-After`. `src/api/service.ts` — адаптер API к интерфейсу: сессии, сообщения, polling, контакты, превью, подтверждение и review. `src/service.ts` — сохранённый моковый сервис. `src/runtime.ts` выбирает режим; `/demo` всегда использует собственные моки.

API-поведение:

- Инициализация создаёт `POST /sessions {}` один раз, в том числе при React StrictMode. Приветствие приходит с сервера. Токены и API-данные хранятся только в памяти; reload создаёт новый чат, старый остаётся в серверном review. Новая сессия закрывает предыдущую через `/close` и не копирует старый контекст.
- `POST /turns` отправляет UUID `client_message_id`. При повторе сохраняются UUID и текст. `202` опрашивается через `GET /turns/{id}` до завершения; `TURN_IN_PROGRESS` ожидает активную операцию. Polling ограничен 45 секундами; отдельный запрос — 12 секундами. Временные ошибки polling имеют не более трёх повторов с backoff. Ручной повтор после timeout получает ту же операцию.
- Сетевые ошибки, `503` и `429` не создают фиктивный ответ. `Retry-After` блокирует повтор до разрешённого времени. Ошибки авторизации/валидации не повторяются автоматически; исходный текст доступен для исправления или безопасного повтора.
- Контакты загружаются через `/lead-draft`; `PATCH` отправляет `expected_revision`. Пустое поле очищается значением `null`. API допускает частичную заявку: достаточно телефона в международном формате, имя и компания необязательны. Без телефона превью можно посмотреть, но подтвердить нельзя.
- «Проверить заявку» вызывает `/lead-preview`. Только после показа серверного резюме и нажатия «Подтвердить заявку» вызывается `/leads`. Ключ `idempotency_key` сохраняется при повторе. `PREVIEW_STALE` обновляет превью и требует нового явного подтверждения; `DRAFT_VERSION_CONFLICT` загружает актуальные поля для повторной проверки.
- После ответа `/leads` интерфейс сообщает о сохранении в демонстрационном прототипе и сохраняет полученный `lead.id`. Передача в CRM не имитируется.

OpenAPI не содержит публичных карточек продуктов, быстрых ответов и показателей уверенности. В API-режиме они не подставляются из моков. Рекомендации и резюме показываются ровно из серверных полей; trace не превращает relevance score в «вероятность правильности». В API нет endpoints архива файлов Energytool: этот экран сохранён как отдельная демонстрация в `/demo`, без выдуманных HTTP-вызовов.

`src/data.ts` содержит реплики и продукты из макетов. `src/demo.ts` — 22 демонстрационных состояния. Компоненты и CSS Modules используют общие переменные из `src/global.css`. SVG экспортированы из Figma в `public/assets`; Inter поставляется локально через `@fontsource/inter`. Временных URL Figma в runtime нет.

Только **моковые** история, сообщения и заявки хранятся под ключом `energytool.mock.v1` в `localStorage`. При первом запуске загружается история из макетов; повреждённый кеш заменяется исходными данными. Для сброса демонстрационных данных удалить этот ключ через DevTools → Application → Local Storage.

## Закрытые история и отладка

Публичный API-режим не обращается к `/review/*` и не показывает переключатель отладки. Для разрешённой проверки задать `VITE_ENABLE_REVIEW=true` и настроить защищённый gateway того же origin по `VITE_REVIEW_BASE_URL` (по умолчанию `/review-api/v1`). Gateway должен аутентифицировать проверяющего и добавлять серверный review bearer. У фронтенда нет поля для ввода или хранения `REVIEW_TOKEN`.

Для **локальной** разработки можно задать непубличные `API_PROXY_TARGET` и `REVIEW_TOKEN` в `.env.local`. Vite проксирует `/review-api/v1` в `/api/v1/review`, подставляя токен на сервере. Этот путь ограничен loopback-подключениями и выключен без токена / разрешения review. Для размещённого production нужен полноценный защищённый reverse proxy; Vite dev middleware не является production-авторизацией.

В разрешённом режиме `/review` загружает все страницы истории и заявок, различает черновики и подтверждённые записи, открывает сессию только для чтения. В чате выбор «Показать источники ответа» запрашивает trace конкретного серверного сообщения. Отображаются реальная задержка, причина решения, документы, chunk ID, фрагменты, версия корпуса и этапы обработки. При отказе в доступе данные не подменяются моками.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
npm run test:api:e2e
```

Vitest + Testing Library проверяют моки, UI и API-контракт (`200/202/409/422/429/503`, UUID при повторе, контакты, stale preview, доступ к review). Playwright проверяет моковый путь и 22 состояния на desktop 1440×960 и mobile 390×844; API-сборка проверяется отдельно с перехваченными ответами по OpenAPI. Скриншоты находятся в `test-results/screens/` и `test-results-api/`. Браузерные наборы используют порт 5173, поэтому перед ними нужно остановить dev-сервер.

В Windows браузерные тесты используют установленный Microsoft Edge. На другой системе перед первым запуском выполнить `npx playwright install chromium`. Конфигурация — `playwright.config.ts`.

## Ограничения прототипа

В моковом режиме ответы детерминированы, а отладка показывает фиктивные показатели и имена документов. Тексты и цены взяты из Figma и не являются актуальным коммерческим предложением. Архив содержит семь исходных строк из макета и дополнительные вымышленные записи для проверки пагинации; скачивается демонстрационный CSV. В API-режиме консультацию выполняет подключаемый сервер: LLM/RAG/backend в этот frontend-проект не входят. Адрес сервера пока не задан; проверка с реальным развернутым backend ещё не выполнялась.

Экраны разделов «Устройства» и «Управление» отсутствуют в выбранных макетах: пункты показывают уведомление об ограничении прототипа. Используйте только тестовые контактные данные. Настоящие персональные данные не следует сохранять в этом локальном прототипе.
